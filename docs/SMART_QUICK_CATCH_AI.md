# Smart Quick Catch: AI foundation

Status: **disabled in production**, reviewed 2026-11-04. No external AI request was made, no key was installed, no billing was activated. Quick Catch never depends on AI.

Current zero-cost work: see [FREE_AI_PROVIDER_REVIEW.md](FREE_AI_PROVIDER_REVIEW.md) and [FREE_AI_RELEASE.md](FREE_AI_RELEASE.md). The production factory now only accepts the pinned Cloudflare candidate after source review; Gemini is retained as an inactive research adapter, with no paid fallback. Local diary analysis and recommendations are usable deterministic calculations, not active model inference.

## Implementation

- `src/features/ai/aiPolicy.js`: independent `species`, `diary`, `recommendations`, `stories` flags, all false; versioned, provider-specific, capability-specific consent and revocation checks. Payload access happens only after both gates pass. These functions do not persist consent. No consent UI is displayed while capabilities are disabled.
- `speciesSuggestion.js`: strict catalogue-key validation using the actual species catalogue. Predictions remain separate suggestions; no measurement fields are accepted. Multiple fish produce unknown. Scores are uncalibrated. Attachment rejects changed revisions/photos, deleted records and an already selected species. A future repository integration must do the revision check and write atomically; calling this pure helper alone is not a cross-device transaction guarantee.
- `diaryAnalysis.js`: deterministic deduplicated counts by species, local fishing hour, month, method and bait; measured-length average/maximum; missing-data counts; period filters; local evidence IDs. The provider summary excludes notes, photos, GPS, water names and record IDs. These are descriptions of recorded catches, not success rates: fishing effort and unsuccessful trips are absent. Small samples carry a caution. No generative calculation is involved.
- `storyDraft.js`: explicit reviewable drafts; original notes are untouched until approval, stale drafts cannot replace newer notes, and title/clarity output cannot replace the notes field. Factual catch measurements remain unchanged. Generated prose still requires human fact review.
- `server/speciesApi.js`: testable, fail-closed server adapter. Mandatory authenticated UID, server-side consent lookup, atomic persistent rate-limit dependency, owner/photo identity checks, 1 KB request limit, 2 MB metadata-stripped image limit, supported MIME types and validated output. It accepts IDs only, no client URL or owner ID. Consent is rechecked after image retrieval immediately before model dispatch. It never mutates a catch or writes raw photo/journal logs.
- `server/productionSpeciesApi.js`: actual production wiring reuses the existing Firebase Admin initialization, project validation (`chutnucz`) and revoked-token verification. It rejects account deletion tombstones, reads persisted consent from `users/{uid}/aiPreferences/consent` (requiring matching `ownerId`), checks catch ownership/photo references and verified Cloudinary `synced` identity/hash, and signs the original through the existing Cloudinary SDK. Download hosts are allowlisted, redirects forbidden, timeout 15 seconds, streamed input capped at 10 MB and bytes checked against stored SHA-256. Per-owner Firestore transactions enforce 3 requests/minute and 20/day with expiring rate records. The baseline JPEG container rewriter removes EXIF/XMP/IPTC/comments/ICC without changing compressed pixels; only the fixed-size Adobe colour marker is retained. Original orientation metadata is removed, so the AI image can be rotated. PNG, WebP, multi-scan/progressive JPEG and images above the 2 MB AI limit fail safely pending a validated image decoder. No Cloudinary transformation or paid image feature was added.
- `server/geminiProvider.js`: real REST transport, server-only key header, timeout, output-size check and strict result validation. Only stripped image bytes and the species catalogue go to the provider. The transport is tested with a local injected response, not a paid inference.
- `/api/ai/species`: calls the real production factory but returns `503 ai_disabled` while the source flag is false; environment variables alone cannot activate it. No SDK enters the initial client bundle.

## Provider research and decision

Gemini supports image input and direct HTTPS requests suitable for a Vercel Node function. Its published quotas depend on account/model and are not capacity guarantees. The current terms require Paid Services for API clients made available in the EEA, Switzerland or UK, and restrict clients likely to be accessed by minors. Unpaid processing has distinct data-use terms with an EEA exception; paid requests may still be logged for abuse prevention. **Do not use a generic free-tier promise for ChytnuCz.** No model or price is pinned until the account, audience, region and budget are approved. Sources: [image input](https://ai.google.dev/gemini-api/docs/image-understanding), [pricing](https://ai.google.dev/gemini-api/docs/pricing), [quotas](https://ai.google.dev/gemini-api/docs/rate-limits), [terms and data use](https://ai.google.dev/gemini-api/terms).

Cloudflare Workers AI is another candidate: published free allocation is 10,000 neurons/day, with requests failing after the free cap unless a paid plan is enabled; paid overage is $0.011/1,000 neurons. A hosted Llama vision model is documented with image support and a zero-retention label. This is not validation of availability for this account, model licence eligibility, Czech fish accuracy, latency, or service-level reliability. No Cloudflare account was connected. Sources: [pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/), [vision model](https://developers.cloudflare.com/workers-ai/models/llama-3.2-11b-vision-instruct/), [data use](https://developers.cloudflare.com/workers-ai/platform/data-usage/).

Transformers.js can run vision classifiers locally through ONNX/WASM or WebGPU. It avoids sending photos to a hosted model after assets are downloaded. This project has no validated Czech freshwater fish model; generic image classification is insufficient evidence of species accuracy. Browser memory, initial model download and iPhone support require measurement. No model was added to the capture bundle. Sources: [Transformers.js](https://huggingface.co/docs/transformers.js/index), [WebGPU guide](https://huggingface.co/docs/transformers.js/guides/webgpu).

Decision: keep all external AI capabilities disabled. No production provider has been selected or falsely represented as free. The Gemini transport is an interchangeable implementation candidate, not an activated service.

## Setup and release blockers

No AI environment variables are required for local insights. Future server-only names are `AI_PROVIDER=cloudflare`, `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN`, `AI_CLOUDFLARE_MODEL=@cf/google/gemma-4-26b-a4b-it`, `AI_SPECIES_ENABLED=true` and `AI_ZERO_COST_CONFIRMED=true`. Source flags remain false; environment variables cannot activate inference alone. A real test and consent/privacy release review remain mandatory. Do not add billing or configure Gemini for the zero-cost path. Existing Firebase project remains `chutnucz`.

Before enabling a capability:

1. Approve the provider/account, terms, age suitability, region and budget. Any chargeable activation needs owner approval.
2. Run emulator and real-account acceptance of the implemented Firebase/Cloudinary wiring. Add a validated image decoder for PNG/WebP/progressive JPEG and large originals; no client metadata-stripping claim is trusted. Test baseline JPEG stripping on actual capture fixtures before enabling it for real users.
3. Provide a persisted consent setting and authenticated server consent write/revoke action naming the actual provider, exact data sent, purpose, controls and retention. The read path is implemented; no consent document is currently created, and current rules do not permit direct client writes to this new path. Revocation is checked before dispatch. Core saving must remain available without consent.
4. Update Privacy Policy to describe actual processing accurately before any real user data leaves the application.
5. Validate representative images, similar species, unclear/no-fish/multi-fish photos and model failures. Measure latency/cost; verify catalogue version compatibility and cross-device manual-override writes.
6. Wire the UI only after end-to-end validation. Story output must be presented for review and explicit approval. Diary explanations must receive aggregates and return evidence-linked hypotheses, never recalculate factual statistics.

No schema migration or second catch/photo queue was introduced. The future consent read path currently has no documents or writer. No external AI-generated data exists to export/delete in this release. Future saved drafts, consent and suggestions must participate in ordinary export/deletion before activation.
