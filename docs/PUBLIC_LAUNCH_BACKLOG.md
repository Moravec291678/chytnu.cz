# ChytnuCz · backlog veřejného vydání

Priority P0 znamenají potvrzenou kritickou chybu. V kontrolovaném rozsahu žádná potvrzena. Při reprodukci ztráty úlovku/fotky, průchodu přes hranici UID, selhání výmazu s veřejně dostupnou projekcí nebo chybě autentizace bez použitelné nápravy eskalovat příslušný blok na P0 a zastavit nábor. P1 je podmínka odpovídajícího vydání. P2 je provozní/UX zlepšení, P3 samostatný produktový milník.

## M1 · Rozsah a kontrola produkce · M · 1–3 pracovní dny

- **REL-01 · P1 · Oddělit skutečný pilot od rozpracovaných funkcí.** `src/app/App.jsx:167–198`, `src/product/config/featureFlags.js`, `src/features/social/server/socialApi.js:5–20`. Obě implementace jsou lokální. Zapnuté dílčí sociální funkce obcházejí hrubou představu „socialNetwork=false vše skryje“. Kořen je dvojí řízení UI a serveru. Stanovit seznam skutečně povolených tras a API operací daného vydání. Zavést test matrice guest/user/owner, přímých URL a API při vypnuté funkci. Zachovat obsah a historii. Dopad zásadní pro web v užším rozsahu; rozsah schvaluje David.
- **REL-02 · P1 · Identita prostředí a pravidla.** `vercel.json`, `firestore.rules:424–624`, `firestore.indexes.json`, `docs/FIREBASE_PRODUCTION_SETUP.md`. Vlastník schválí či deleguje read-only přístup a oddělení pilotu.

### Zásahy při provozním incidentu

- **Web nedostupný / špatný release:** odečíst status domény, assety a SHA, při regresi vrátit poslední schválený kompatibilní Vercel build. Ověřit i offline shell, frontu a nasazená rules. Zálohy a uživatelská data ponechat.
- **Login:** ověřit přes schválený syntetický účet e-mail a zvlášť OAuth. Zkontrolovat authorized domains a šablony. Pokud funguje guest, odlišit jej jako lokální profil. Nevynucovat přihlášení při rozpracovaném offline záznamu.
- **Úlovek/Sync:** uchovat lokální export a stav fronty; ověřit skupinu chyb, revizi, autorizaci a čas. Testovat s neprodukčními daty. Zastavit opakování, pokud se potvrzuje neoprávněné přepsání nebo ztráta. Nepoužívat plošné vymazání cache.
- **Foto/CDN:** porovnat podepsání, upload, verifikaci, doručení a vykreslení. Zachovat lokální blob, omezit nepovinné cloudové funkce, zkontrolovat kredit a stav Cloudinary. Po obnově ověřit retry a odstranění pozdních sirotků.
- **Soukromí:** uzavřít dotčené serverové čtení, zachovat minimální autorizovanou evidenci bez citlivého payloadu, ověřit revokaci a stav CDN, informovat vlastníka. Zákonné oznamování a lhůty posoudit s odpovědnou osobou.
- **Kvóta/moderace:** omezit nábor, feed, deriváty a nákladné operace; monitorovat backlog. U reportu informovat oprávněného moderátora, zaznamenat rozhodnutí a ponechat cestu k odvolání, pokud je v rozsahu. Žádná automatická aktivace placeného plánu.

### Konkrétní zbytková rizika k ověření

- **RISK-01 · P1 při zapnutém cloud uploadu.** Limit 10 MiB v `src/product/config/limits.js` a kontrola po uploadu nemusejí zastavit spotřebu přenosu ještě před ověřením. V soukromém sandboxu prověř skutečný provider limit a životnost grantů malým smluveným testem. Aktivní limity zapiš, přidej negativní test odmítnutí a úklidu; případy zneužití klasifikuj až podle skutečného výsledku. Složitost M, závisí REL-03.
- **RISK-02 · P2 zpevnění, P1 pouze při nálezu.** `vercel.json` má nosniff, referrer a permission policy, bez explicitní CSP. Nejprve inventář zdrojů (Firebase/OAuth, Cloudinary, OSM, Open-Meteo, blob a worker). Vyzkoušet report-only na preview a doplnit end-to-end zajištění map, sign-in, sdílení a SW před enforcementem. Absence CSP sama nepotvrzuje XSS. Složitost M.
- **RISK-03 · P2 zřetelné duplicity revíru.** Oddělený offline výběr stejného catalogueId na dvou dosud nesynchronizovaných zařízeních může založit dva lokální Water. Repro prostřednictvím dvou čistých scope stejného účtu a pozdější sync, datový předpoklad je zdokumentován v RIS_CATALOGUE bez nového browser testu. Řešit bezpečnou detekcí a uživatelem potvrzeným sloučením při zachování ID a vazeb, nikdy automatickým přepsáním. Složitost L, navazuje na REL-04.
